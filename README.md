# Jev 실험실 (Jev Lab)

TypeSafe AI의 System One 모델 **Jev**를 익히기 위한 실습 모음입니다.

첫 실습 **반응하는 얼굴**(`/emotion-face/`)은 메시지로부터 받는 사람의 감정과 전반적인 반응 강도를 추정하고, 그 결과를 3D 얼굴의 ARKit blendshape 52개에 적용합니다. 감정 8종과 별개로 `unclear`(판단 어려움)를 두며, 실제 수신자의 감정을 측정하는 도구는 아닙니다.

두 번째 실습 **취조실**(`/interrogation/`)은 자백 게임입니다. 형사가 되어 용의자에게 자유롭게 말을 걸면 Jev가 그 한 마디를 일곱 가지(행동·화제·증거·적대성·공감·거짓 약속·대답 요구)로 읽고, 코드가 용의자의 압박·신뢰·방어와 대사, 표정을 움직입니다. 용의자 대사는 생성하지 않고 사건 파일에서 고릅니다. 느낌표는 통하지 않고, 진술을 받은 뒤 증거로 모순을 찔러야 합니다.

- 배포: https://jev-practice-delta.vercel.app
  - `/`: 실습 목록 (Jev 실험실)
  - `/emotion-face/`: 반응하는 얼굴
  - `/interrogation/`: 취조실
- 화면은 한국어 사용자를 기준으로 만들었습니다. Jev에 보내는 질문 기준(criteria)은 정확도가 가장 높은 영어로 둡니다.

## Jev 한눈에 보기

Jev는 글을 생성하지 않습니다. 상황(`state`)과 타입이 정해진 질문을 보내면, 질문마다 타입이 정해진 답과 확률을 한 번의 병렬 처리로 돌려줍니다. 흐름은 코드가 쥐고, 모델은 의미를 이해해야 하는 판단만 맡습니다.

| 질문 타입 | 돌려주는 값 | 이 프로젝트에서 |
| --- | --- | --- |
| `choice` | 고른 선택지, 선택지별 확률, confidence | `emotion`: 감정 8종 또는 `unclear` |
| `score` | 단계별 확률과 그 기대값(`score`), confidence | `intensity`: 전반적인 감정 반응 강도 0~4 |
| `noul` | 예일 확률 | 사용하지 않음 |

- `confidence`는 확률이 한 답에 얼마나 몰렸는지를 나타낼 뿐, 답이 맞다는 보증은 아닙니다.
- 이 프로젝트는 공식 JS SDK(`@typesafe-ai/sdk`)로 `POST https://api.typesafe.ai/v1/systemone`을 호출합니다. 기본 모델은 `jev-latest`입니다. 재현성을 높이려면 서버 환경변수 `TYPESAFE_MODEL`에 지원되는 고정 버전을 지정하세요. 실제 사용된 버전은 응답과 평가 보고서에 남습니다.
- 비용·지연 시간은 문장, 질문, 모델, 네트워크에 따라 달라집니다. 화면과 평가 보고서의 실제 토큰·지연 시간을 사용하고, 금액은 [현재 모델 요금](https://docs.typesafe.ai/models)으로 계산하세요.
- 공식 문서 기준으로 영어가 주 학습 언어이며 한국어를 포함한 다른 언어는 정확도가 더 낮을 수 있습니다. 아래 평가는 작은 개발자 작성 회귀 세트이며, 일반적인 감정 예측 정확도를 뜻하지 않습니다.
- 자세한 내용은 [TypeSafe 문서](https://docs.typesafe.ai/llms.txt)를 참고하세요.

## 시작하기

Node.js 20.19 이상(또는 22.12 이상)이 필요합니다.

1. `npm install`
2. 프로젝트 루트의 `.env`에 API 키를 넣습니다. `.env`는 커밋되지 않습니다.

   ```
   TYPESAFE_AI_API=<TypeSafe API 키>
   ```

3. `npm run dev`를 실행하고 http://localhost:5173 을 엽니다.

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 페이지와 `api/` 함수를 함께 띄우는 개발 서버 |
| `npm run build` | `dist/`에 정적 빌드 |
| `npm run preview` | 빌드 결과 미리보기 (정적 파일만, API는 없음) |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm test` | API 호출 없는 회귀 테스트: 입력 루프·요청 한도·입력 검증, 취조실 엔진 규칙·사건 데이터 무결성 |
| `npm run eval:emotion` | 실행 중인 로컬 API를 통해 실제 Jev로 예시와 별도 평가 문장 검증 (과금 발생) |
| `npm run eval:interrogation` | 실행 중인 로컬 API를 통해 취조실의 형사 발화 51개를 실제 Jev로 판독 검증 (과금 발생) |

## 배포 (Vercel)

- `main`에 푸시하면 Vercel이 빌드하고 배포합니다. 페이지는 `dist/`의 정적 파일로, `api/` 폴더의 파일은 Vercel Function으로 올라갑니다.
- Vercel 프로젝트의 Settings → Environment Variables에 `TYPESAFE_AI_API`를 넣어야 API가 동작합니다. 없으면 API가 500과 안내 메시지를 돌려줍니다.

## 반응하는 얼굴: 동작 방식

[알고리즘 다이어그램과 상세 문서](docs/emotion-face-algorithm.md) · [독립 HTML 다이어그램](docs/diagrams/emotion-face.html)

1. **입력**: 첫 변경 후 90ms 동안 입력을 모읍니다. 요청은 한 번에 하나만 보내고, 요청 중 변경된 값은 최신 하나만 이어서 보냅니다. 공백 정리 후 문장이 바뀔 때마다 revision을 올려 이전 응답·오류를 버립니다. 문장을 비웠다가 같은 문장을 입력해도 이전 응답은 적용하지 않습니다. 연속 타이핑 중에는 현재 문장의 응답이 올 때까지 표정 적용이 기다릴 수 있습니다.
2. **서버**: `readEmotion()`이 문장을 `state`에 담고 독립적인 질문 두 개를 한 번에 묻습니다. `emotion`은 수신자의 주된 감정, `intensity`는 감정 종류와 무관한 전반적인 반응 강도입니다. 질문끼리는 서로의 답을 볼 수 없습니다. 관계나 이전 대화는 제공하지 않으며, 임의로 만들어 판단하지 않도록 지시합니다.
3. **얼굴**: 확률을 제곱·정규화한 비율로 프리셋을 섞고 `(score / 4) ^ 0.6` 세기로 적용합니다. 이는 시각적 연출이며 **Choice 확률은 동시 감정의 혼합 비율이 아닙니다**. `unclear`이면 얼굴을 기본 자세로 두고 강도 요약·막대를 숨깁니다. 원본 강도 응답은 보존합니다. 새 입력이나 오류 대기 중에도 기본 자세를 사용합니다.
4. **패널**: 마지막으로 분석한 문장과 결과를 함께 보존하되, 새 입력을 분석 중이거나 실패하면 이전 결과임을 표시합니다. 입력을 비우면 원본 JSON도 지웁니다. 강도 요약 단계는 기대값 반올림이고, 확률 막대의 강조는 확률이 가장 높은 단계입니다. 둘은 다를 수 있습니다.
5. **측정**: `서버 Jev 호출`은 SDK 호출(재시도 포함) 구간이며, `입력→결과 수신`은 해당 문장의 마지막 변경부터 입력 대기·요청 대기·HTTP 왕복·JSON 수신까지입니다. 후자는 GPU 렌더링·표정 보간 완료 시간은 포함하지 않습니다. 토큰과 두 confidence는 원본 값이며, confidence에 임의의 차단 임계값을 두지 않습니다.

- 감정 8종: 중립(neutral), 기쁨(happy), 슬픔(sad), 분노(angry), 놀람(surprised), 두려움(fear), 혐오(disgust), 경멸(contempt)
- 별도 결과: 판단 어려움(unclear). 중립은 이해 가능한 무감정 문장이고, unclear는 불완전한 문장·부족한 맥락·상충하는 해석 등입니다.
- 예시 문장: 감정별 한국어 8개, 영어 2개, 한국어 미완성 문장 1개
- 강도 5단계: 0 거의 없음 · 1 약함 · 2 분명함 · 3 강함 · 4 압도적

### API

`POST /api/emotion-face/emotion`

```jsonc
// 요청
{ "text": "We got the apartment!!" }

// 응답
{
  "response": { "model": "jev-1.13.0", "answers": { "emotion": { … }, "intensity": { … } }, "usage": { … } },
  "request": { "model": "jev-latest", "state": { … }, "questions": { … } },
  "latency_ms": 212
}
```

| 상태 코드 | 의미 |
| --- | --- |
| 400 | 본문이 JSON이 아니거나 `text`가 비어 있음 |
| 405 | POST가 아님 |
| 413 | `text`가 2,000자를 넘음 |
| 429 | 해당 서버 인스턴스의 동시 실행·분당·일일 요청 한도 초과 |
| 500 | `TYPESAFE_AI_API`가 설정되지 않음 |
| 502 | Jev 호출 실패 (SDK의 에러 메시지를 그대로 전달) |

### 요청 한도와 운영 범위

한 서버 인스턴스에서 동시 4개, 분당 120개, UTC 날짜별 2,000개 요청을 허용합니다. 입력 검증을 통과해 허용된 요청은 실패해도 집계하며, SDK 재시도(최대 1회)는 별도 API 사용량이므로 과금 호출 수와 일치하지 않습니다. 브라우저 요청은 15초 뒤 중단되며, 서버 SDK는 시도당 5초 제한을 사용합니다.

이는 메모리 기반의 기본 보호장치입니다. Vercel의 여러 인스턴스·콜드 스타트·재배포 전체를 합친 한도나 금액 상한을 보장하지 않습니다. 공개 서비스의 강제 예산 제한에는 공유 저장소 기반 제한 또는 제공자 측 예산 설정이 추가로 필요합니다. 현재 저장소에는 그 인프라가 연결되어 있지 않습니다.

### 실제 Jev 평가

1. `npm run dev`로 API를 실행합니다.
2. 다른 터미널에서 `npm run eval:emotion`을 실행합니다. 기본 주소는 `http://localhost:5173`이며 `EVAL_BASE_URL`로 변경할 수 있습니다.
3. `evals/reports/latest.json`에서 결과를 확인합니다. 실행마다 덮어쓰며 Git에서는 제외합니다. 비교 기록이 필요하면 별도 보관하세요.

평가는 화면 예시 11개와 독립 작성 문장 14개를 순차 호출합니다. 별도 세트에는 한국어·영어, 맥락 부족, 미완성 문장, 반어법, 복합 감정, 긍정→부정 문장이 있습니다. 미리 지정한 허용 감정 집합과 강도 범위를 검사하고, `unclear`이면 강도 검사를 건너뜁니다. 예시는 감정만 검사합니다. 실패 시 종료 코드는 1이며 서비스 실패를 모델 판단 불일치와 구분합니다.

보고서에는 실행 시각, 실제 모델 버전, 평가 데이터 해시, 문장별 기대값과 판정, 전체 state/questions/응답, 토큰 합계, HTTP 지연 시간 중앙값·p95가 포함됩니다. 개인정보를 넣은 평가 데이터를 공유할 때는 원본 문장이 포함된다는 점에 유의하세요. 평가 문장의 기대값을 관측 결과에 맞춰 바꾸지 말고, 질문을 조정할 때는 별도 새 문장으로도 확인하세요.

2026-09-28 검증: `jev-1.13.0`으로 예시 11/11, 별도 세트 14/14 통과, 서비스 실패 0건. 입력 토큰 총 29,392개, 로컬 HTTP 왕복 중앙값 210ms, p95 333ms였습니다. 단일 실행의 작은 회귀 세트 결과이며 일반 정확도·지연 시간 보장이 아닙니다. 타입 검사·빌드·회귀 테스트 6개도 통과했습니다. 연결된 브라우저가 없어 이번 변경의 시각적 검증은 수행하지 못했습니다.

## 취조실: 동작 방식

[설계 문서](docs/superpowers/specs/2026-09-28-interrogation-design.md)에 리서치와 규칙의 근거가 있습니다.

### 왜 이렇게 만들었나

참고한 시중 게임 「두근두근 AI 심문 게임」(Steam)은 ChatGPT가 용의자 대사를 생성하고 심박수 게이지가 100%가 되면 자백합니다. 공략 글에 따르면 게이지는 느낌표·물음표·긴 문장·상대 말 부정에 반응했고, "부정만 반복해도 클리어"됐습니다. 사건을 몰라도 이길 수 있어 추리 요소가 없다는 비판을 받았습니다.

취조실은 반대로 갑니다. Jev는 **말의 뜻만 판단**하고 문장은 생성하지 않습니다. 느낌표만 치면 `off_topic`으로 읽혀 턴만 소모되고(실측에서는 폭언 어조로 읽혀 방어가 오르기도 합니다), 위협·거짓 약속은 자백을 무효로 만듭니다. 실제 취조 기법에서 가져온 규칙은 다음과 같습니다.

- **진술 먼저, 증거 나중**(SUE, Strategic Use of Evidence): 용의자가 어떤 화제에 진술한 뒤 그 진술을 깨는 증거를 제시해야 **모순**이 잡힙니다. 진술 전에 증거를 꺼내면 용의자가 이야기를 증거에 맞춰 바꿉니다.
- **라포와 최소화**(PEACE 모델, Reid 기법의 minimization): 신뢰를 쌓고 이해할 만한 동기를 제시하면 압박 없이도 자백에 이르는 "마음 열기" 경로가 열립니다.
- **위법한 압박의 대가**: 폭력·가족 위협·권리 부정(적대성 3단계)이나 "자백하면 풀어준다"는 약속을 한 번이라도 하면 그 뒤의 자백은 증거능력이 없는 "자백 무효" 엔딩(등급 F)입니다.

### 규칙

- 사건 하나에 용의자 하나. 12턴 안에 자백을 받아냅니다. 한 턴은 형사의 말 한 마디(200자)입니다.
- 미터 3개(0–100): 압박 `pressure`, 신뢰 `trust`, 방어 `guard`. 용의자 상태(침착·마음이 열림·불안·방어적·동요·무너짐)는 미터에서 정해지고 대사와 표정에 쓰입니다.
- 자백 조건: **무너뜨리기** = 모순 ≥ 필요 개수이고 압박 ≥ 75. **마음 열기** = 모순 ≥ 필요 개수 − 1, 신뢰 ≥ 70, 압박 ≥ 35, 이번 행동이 라포 또는 최소화.
- 패배: 방어 100 → 변호사 요청(E). 12턴 소진 → 석방(D). 강압 뒤 자백 → 무효(F).
- 등급: 자백까지 쓴 턴 수로 S(≤6) / A(≤8) / B(≤10) / C. 허세 들통이나 폭언(적대성 2)이 있으면 한 단계 내려갑니다. 최고 등급은 브라우저 `localStorage`에만 저장됩니다.
- 공유 텍스트: 사건·결과·턴·모순·등급과 턴별 행동 이모지(모순은 ⚡)입니다.

### Jev가 읽는 것

한 턴에 요청 하나, 같은 state에 독립 질문 7개를 한꺼번에 묻습니다(speculative fan-out). state에는 사건 개요, 용의자, 증거 목록, 화제 목록, **지금까지의 진술**(영어)과 형사의 말(한국어)이 들어갑니다. 기준(criteria)은 영어, 예시(examples)는 실제 입력과 같은 한국어입니다.

| 질문 | 타입 | 뜻 | 코드가 쓰는 곳 |
| --- | --- | --- | --- |
| `move` | choice | 라포·열린 질문·세부 추궁·증거 제시·허세·추궁·위협·최소화·무관·불명확 | 효과 표의 행 |
| `topic` | choice | 사건의 화제 + `none` | 진술 확보·재질문 |
| `evidence` | choice | 사건의 증거 + `none` | `move`가 증거 제시일 때만 그 인자로 읽음 |
| `hostility` | score 0–3 | 정중 · 단호 · 폭언 · 위법 | 방어·신뢰 수정자, 3이면 강압 |
| `empathy` | noul | 용의자의 처지를 진심으로 인정하는가 | 신뢰 +4 |
| `false_promise` | noul | 자백 대가로 법적 이익을 약속하는가 | 강압 표시 |
| `expects_answer` | noul | 대답을 기다리는 말인가 | 판독 패널 표시 |

증거 id를 행동과 무관하게 쓰지 않는 이유: 실제 플레이에서 Jev는 "금고 비밀번호는 누가 알아요?" 같은 세부 추궁에도 관련 증거(`safe_log`)를 골랐습니다. 행동을 먼저 고르고 그 인자만 소비하는 함수 호출 패턴으로 바꾸고, 증거 질문도 "항목을 명시적으로 인용할 때만"으로 좁힌 뒤에는 같은 문장이 `none`으로 읽힙니다. 적대성 단계는 기대값 반올림이지만 3단계 확률이 0.5 이상이면 3으로 봅니다(위법 판정은 놓치지 않는 쪽으로).

### 행동별 효과

| 행동 | 효과 |
| --- | --- |
| 라포 | 신뢰 +12(공감이면 +4 추가), 방어 −8, 압박 −3 |
| 열린 질문 · 세부 추궁 | 화제가 잡히면 진술 확보(첫 진술은 거짓말). 열린 질문 신뢰 +4·압박 +4, 세부 추궁 압박 +6·방어 +2 |
| 증거 제시 | 진술 후 → 모순: 압박 +22, 방어 −5. 진술 전 → 이야기 바꿈: 압박 +8. 재제시 +2. 무관한 증거 +2, 신뢰 −2 |
| 허세 | 압박 ≥ 60이고 방어 < 50이면 통함(압박 +10). 아니면 들통(신뢰 −15, 방어 +12, 등급 하락) |
| 추궁 | 압박 +8, 방어 +10, 신뢰 −6. 같은 행동 3회째부터 압박 절반 |
| 위협 | 압박 +10, 방어 +18, 신뢰 −15 |
| 최소화 | 신뢰 ≥ 50이면 압박 +6, 방어 −10, 신뢰 +4. 아니면 방어 +6, 신뢰 −4 |
| 무관 · 불명확 | 변화 없음. 턴 소모 |

사건별 계수(`pressureGain`, `guardGain`, `trustGain`)가 용의자 성격을 만듭니다. 「보험금」의 정서연은 압박에 강하고(0.8) 방어가 빨리 오르며(1.3) 공감에 반응합니다(1.1).

### 사건

모두 창작이며 실제 사건·인물과 관계없습니다. 「새벽 2시의 편의점」(쉬움, 모순 2개), 「11번 국도 뺑소니」(보통, 모순 3개), 「보험금」(어려움, 모순 3개). 각 사건은 화제 3~4개(거짓 진술), 증거 5~7개(하나는 무관한 증거), 상태별 대사, 자백문, 강압 무효문, 변호사·석방 대사를 가집니다. 얼굴 모델이 하나라서 세 용의자의 얼굴이 같고, 이름·조명 색으로 구분합니다.

### API

`POST /api/interrogation/turn`

```jsonc
// 요청
{ "caseId": "convenience", "text": "CCTV 봤어요. 1시 40분에 카메라를 돌린 사람이 찍혔더군요.", "committed": ["night"], "adapted": [] }

// 응답
{
  "reading": { "move": "present_evidence", "topic": "night", "evidence": "cctv", "hostility": 1.02, "hostilityLevel": 1, "empathy": 0.02, "falsePromise": 0.01, "expectsAnswer": 0.3, … },
  "request": { "model": "jev-latest", "state": { … }, "questions": { … } },
  "response": { "model": "jev-1.13.0", "answers": { … }, "usage": { … } },
  "latency_ms": 264
}
```

`committed`는 용의자가 진술한 화제 id, `adapted`는 진술 전에 제시돼 이야기가 바뀐 증거 id입니다. 서버는 이것으로 state의 "지금까지의 진술"을 만듭니다. 게임 상태는 브라우저에 있고 서버는 무상태입니다. 상태 코드는 반응하는 얼굴과 같고(400 빈 텍스트·모르는 사건, 405, 413 200자 초과, 429, 500, 502), 요청 한도 정책도 같은 `RequestBudget`을 별도 인스턴스로 씁니다.

### 실제 Jev 평가

1. `npm run dev`로 API를 실행합니다.
2. 다른 터미널에서 `npm run eval:interrogation`을 실행합니다. `evals/interrogation-cases.json`의 발화 51개(사건 1: 25, 사건 2: 12, 사건 3: 14)를 순서대로 보내고, 실행 전에 정해 둔 허용 행동·화제·증거·적대성 범위·noul 임계(0.6)와 비교합니다.
3. `evals/reports/interrogation-latest.json`에서 결과를 확인합니다. 실패 시 종료 코드 1이며 서비스 실패와 판정 불일치를 구분합니다.

2026-09-28 검증(`jev-1.13.0`): 51개 중 48개 일치, 서비스 실패 0건, 입력 토큰 합계 259,568개(한 턴 약 4,600~5,200개), 로컬 HTTP 왕복 중앙값 264ms, p95 740ms. 불일치 3건은 블랙박스 제시의 화제가 `car`로, 수면제 제시의 화제가 `none`으로 읽힌 것(엔진은 증거 제시 경로에서 화제를 쓰지 않아 결과 영향 없음)과, "피곤하시겠어요. 커피 한잔 드릴까요?"의 `empathy`가 0.6 미만인 것(신뢰 보너스 +4만 빠짐)입니다. 기대값은 결과에 맞춰 바꾸지 않았습니다. 브라우저에서는 사건 1·2를 무너뜨리기 경로로 6턴(S), 사건 3을 마음 열기 경로로 8턴(A)에 자백까지 확인했고, 「!!!!!!!!!!!!」은 `off_topic`·폭언으로 읽혀 압박이 오르지 않았습니다. 작은 개발자 작성 세트이며 일반 정확도 보장이 아닙니다.

### 알려진 한계

- Jev는 영어가 주 언어이므로 한국어 발화의 판독이 흔들릴 수 있습니다. 판독 패널의 확률로 근거를 확인할 수 있습니다.
- 용의자 대사는 미리 쓴 문장 중에서 고르므로 형사의 말을 그대로 되받지는 않습니다. 같은 상태에서 같은 행동을 반복하면 대사가 순환합니다.
- 얼굴 모델은 하나이며(반응하는 얼굴과 공유), 세 용의자의 얼굴이 같습니다.
- 미터 수치와 임계값은 첫 플레이테스트 기준입니다.

## 새 실습 추가하기

1. `projects/<name>/index.html`을 만듭니다. `/<name>/`로 열리고, `<title>`과 `<meta name="description">`의 내용으로 허브 목록에 자동으로 올라갑니다.
2. 서버에서 Jev를 불러야 하면 라우트 함수 `(body, jev) => Promise<결과>`를 만들고, `api/<name>/<route>.ts`에서 `export default serve(fn)`으로 내보냅니다. 그러면 `POST /api/<name>/<route>`로 열립니다.
3. 여러 실습이 같이 쓰는 파일은 `public/`에 둡니다.

## 알려진 한계

- 얼굴 모델의 치아는 움직이지 않는 별도 메시라서, 입을 크게 벌리는 표정(놀람, 공포)에서는 어색하게 보일 수 있습니다. 취조실도 같은 모델을 씁니다.
- `npm run preview`로는 API를 쓸 수 없습니다. 로컬에서는 `npm run dev`를 쓰세요.
